Logic · Analysis · Debugging

My Problem-Solving Approach

I handle technical challenges by understanding the issue first, breaking it into smaller tasks, testing a practical solution, and checking the result. These are the steps I use to learn from errors and improve my projects.

01 Analyze

Understand the Problem

Identify what should happen, what actually happens, and the steps needed to reproduce the issue.

02 Break Down

Check One Part at a Time

Separate the user interface, application logic, data, or hardware behavior so the likely cause is easier to find.

03 Debug

Test a Practical Fix

Use browser tools, validation, logs, and small changes to test possible solutions without changing too many things at once.

04 Verify

Retest and Improve

Check the normal workflow and edge cases again, then improve the code or circuit so the solution is easier to maintain.

Applied to my projects

Examples of Thinking Through a Challenge

CASE 01 / WEB TapSeafood

Making the cart and checkout more reliable

Challenge

Order totals can become incorrect when quantities change, or checkout details are missing.

My approach

Check quantity and price calculations separately, validate required customer fields, and test changes such as increasing an item quantity or submitting incomplete details.

What I focus on

Clear totals, useful validation messages, and a consistent ordering flow.

CASE 02 / WEB GrandStay

Checking booking dates and stay costs

Challenge

Invalid date ranges can cause incorrect stay lengths or confusing reservation totals.

My approach

Validate check-in and check-out dates, calculate the number of nights, review the price calculation, and test invalid or conflicting date ranges before confirming a booking.

What I focus on

Accurate calculations, understandable errors, and a clear reservation process.

CASE 03 / HARDWARE SmartDispense

Handling sensor detection and pump timing

Challenge

The dispenser needs to respond to a nearby cup and avoid leaving the pump running longer than intended.

My approach

Check ultrasonic distance readings, confirm the trigger condition, test relay and pump behavior, and include a timed shutoff in the control logic.

What I focus on

Reliable detection, predictable operation, and a clear status message for the user.

My debugging checklist

I prefer to fix the cause of an issue rather than only hide the symptom, and I retest after making changes.

Reproduce the issue Read console or logs Trace input to output Test edge cases Retest the workflow Document the fix
